The problem

Gateways forward the easy half.

Aggregating tools/list and tools/call is the part everyone does. The other half — a server asking the agent a question, a call that takes ten minutes, a session that has to survive a restart — is the part that breaks real setups. And nobody shows you what the whole thing costs per turn.

Configuration

One file. Secrets referenced, never embedded.

No database and no panel writing state behind your back. Anything resolved from ${env:…} or ${file:…} is registered for redaction, so it cannot reach a log line even by accident. 

# jackfield.yaml — the whole gateway
upstreams:
  github:
    transport: http
    url: https://example.com/mcp
    token: ${file:/etc/jackfield/secrets/github.token}

  notes:
    transport: stdio              # a child process
    command: npx
    args: ["-y", "some-mcp-server"]

  porkbun:
    transport: cli                # 120 tools → 1
    commands:
      porkbun:
        description: "Porkbun CLI. Ask it for --help first."
        executable: porkbun
        allowedSubcommands: ["domain", "dns"]

  browser:
    transport: executor           # on a machine of yours
    executor: home

permissions:                     # a floor every client inherits
  - tools: ["*.delete_*"]
    action: ask                  # asks the user, through an MCP form

profiles:
  core:  { upstreams: ["tag:personal"] }
  full:  { extends: [core], upstreams: ["*"] }

clients:
  laptop:
    key: ${file:/etc/jackfield/secrets/key-laptop}
    profile: full

  web-agent:
    key: ${file:/etc/jackfield/secrets/key-web}
    keyInPath: true             # /k/<key>/mcp
    profile: core

  thrifty:
    key: ${file:/etc/jackfield/secrets/key-thrifty}
    profile: full
    expose: search             # find_tool + call_tool
Quickstart

It ships with a working example.

Two MCP servers, three clients, nothing to install and no network needed.

git clone https://github.com/PabloPC05/jackfield && cd jackfield
npm install && npm run build

jackfield check  -c examples/jackfield.yaml   # does everything connect?
jackfield tools  -c examples/jackfield.yaml --by-source
jackfield routes -c examples/jackfield.yaml   # what to paste into each agent
jackfield serve  -c examples/jackfield.yaml
$ jackfield tools --by-source

Run it

Hosting is a choice, not an architecture.

The HTTP layer is written against Web Request/Response, so the same gateway runs as a process, in a container, on NixOS, or in a serverless function. What a host cannot do, an executor on a machine you own does — so the host never gets to decide what your tools may be.

WhereHowCaveat
A processjackfield serveEverything works. The default.
systemddeploy/systemdHardened unit; one read-only secrets directory.
Dockerdeploy/dockerMount secrets as files, not env vars.
NixOSservices.jackfieldConfig goes to the world-readable store, so secrets are file references.
ServerlesscreateWebHandlerNeeds stateless: true: no sessions, no forms, no child processes. Platform specifics not yet verified live.
Your machinejackfield-executorThe half that needs a process. Reach it over a private network.
Compared

Several of the alternatives are better than this one.

Just not at the same things. Written from each project's own documentation in November 2026; these projects move, and most published comparisons of MCP gateways are written by one of the vendors in them — including, in a sense, this one.

agentgateway

A general-purpose agent proxy under a foundation, configured by file. Far more mature, and much broader. Start there if you want one proven proxy for everything.

ToolHive

Runs each MCP server in a container and has the same kind of find_tool optimiser. Its isolation has no equivalent here.

ContextForge · MetaMCP · Obot

Web UIs, upstream OAuth with stored credentials, team auditing. The right answer if you want to add servers by clicking; the opposite trade to a file in git.

Docker MCP Gateway · MCPHub · Bifrost

Container profiles, hub-style discovery, high-throughput proxying. Worth a look if one of those is your emphasis.

What Jackfield is not: mature. It is new, it has not run for long in production, and its interfaces may change before 1.0. It has no container isolation, no UI to add servers, no upstream OAuth, and no multi-tenant auditing. What it has is the half of MCP the others drop, and a configuration you can read in a diff.
